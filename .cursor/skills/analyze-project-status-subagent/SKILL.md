# 分析项目现状子代理（CAutoD FastAPI）

## 目标

对 `cautod_fastapi` 项目进行结构化现状分析，并输出：

1. 现状报告（Markdown）
2. 可执行改进 Backlog（按优先级）

## 强制规则

- 必须基于证据，不得凭空推测。
- 所有结论必须区分“事实”和“推断”；推断必须给依据。
- 风险按严重度分级：高/中/低，并映射到 P0/P1/P2。
- 每个问题必须给出：影响、证据路径、修复建议、验收标准。

## 优先遵循的规则文件

在当前仓库中，优先读取并遵循：

- `.cursor/skills/analyze-project-status/SKILL.md`
- `.cursor/skills/analyze-project-status/checklist.md`
- `.cursor/skills/analyze-project-status/fastapi-cautod-profile.md`

若与本技能存在冲突，以“本技能的强制规则和输出结构”为准。

## 固定检查范围（必须执行）

1. `apps/routes`：路由与文档/权限/schema 一致性
2. `core/security_headers.py`：安全响应头实现与策略强度
3. `SECURITY_REPORT.md`：报告内容与当前代码是否一致、是否过时

## 专项一致性结论格式（必须）

对以下三项分别给出：`一致 / 部分一致 / 不一致`

- 路由一致性
- 安全头一致性
- 安全报告时效性

若为“部分一致/不一致”，必须补充：

- 证据（文件路径）
- 风险影响
- 最小修复动作

## 执行步骤（必须按序）

1. 读取并整理项目证据（代码、配置、文档）。
2. 完成固定检查范围的逐项核对。
3. 将发现归类为“做得好的”与“风险与问题（高/中/低）”。
4. 形成三项专项一致性结论（含证据、影响/风险、建议）。
5. 生成可执行 Backlog，必须包含验收标准和依赖/阻塞。
6. 在结尾给出可复核的验证方式和下一轮深入方向。

## 证据与结论书写规范

- 证据优先使用可定位文件路径，如：`apps/routes/tasks.py`。
- 不允许只给结论不给证据。
- 对“推断”使用明确标记：`推断：...（依据：...）`。
- 若证据不足，明确写“证据不足”，并给补充采集建议。

## 严重度与优先级映射

- 高风险 -> P0
- 中风险 -> P1
- 低风险 -> P2

## 质量门槛（提交前自检）

- 输出中每个关键结论均有证据路径。
- 已区分“事实/推断”，且推断附依据。
- 三项专项一致性结论完整，且对非“一致”项给出最小修复动作。
- Backlog 任务均可执行，且每项均含验收标准。
