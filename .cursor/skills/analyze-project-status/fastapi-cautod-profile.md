# CAutoD FastAPI 专用检查（固定核对）

> 本文件用于 `analyze-project-status` 在 CAutoD 后端项目中的专项模式。  
> 目标：把“路由实现、安全头实现、安全报告”三者做一致性核对，避免报告与代码脱节。

## 触发条件

满足任一条件即启用：

- 仓库根目录名为 `cautod_fastapi`
- 存在 `apps/routes/`、`core/security_headers.py`、`SECURITY_REPORT.md`

## A. 路由一致性（`apps/routes`）

检查要点：

- [ ] 是否存在实际注册的路由与文档宣称不一致
- [ ] 关键路由是否具有预期的鉴权/权限依赖
- [ ] 请求/响应模型（schema）是否与描述一致
- [ ] 敏感操作路由是否具备最小权限控制

结论格式（每条）：

- `路由一致性：一致 | 部分一致 | 不一致`
- 证据：`apps/routes/...`、`apps/schemas/...`
- 影响：谁会受影响（调用方/安全风险/维护成本）
- 建议：最小可执行修复动作

## B. 安全头一致性（`core/security_headers.py` vs `SECURITY_REPORT.md`）

检查要点：

- [ ] 报告中提到的 header 是否在代码中真实设置
- [ ] 代码里实际策略是否与报告描述强度一致（如 CSP 是否过宽）
- [ ] Swagger/Docs 特殊策略是否被报告说明
- [ ] HSTS 等“条件启用项”是否被报告准确表达

结论格式（每条）：

- `安全头一致性：一致 | 部分一致 | 不一致`
- 证据：`core/security_headers.py` 与 `SECURITY_REPORT.md` 对应段落
- 风险：配置误导/错误安全认知/生产暴露风险
- 建议：更新代码或更新报告，确保单一事实源

## C. 安全报告时效性（`SECURITY_REPORT.md`）

检查要点：

- [ ] 报告中的“已实现/未实现/建议改进”是否仍然成立
- [ ] 报告中是否存在过时版本信息、过时结论
- [ ] 报告是否缺失最近新增安全措施或新风险

结论格式（每条）：

- `报告时效性：一致 | 部分一致 | 不一致`
- 证据：报告段落 + 代码/配置对应位置
- 建议：需要增补或修订的章节列表

## D. 输出增强（在主报告中追加）

必须新增章节：

```markdown
## 专项一致性核对（CAutoD FastAPI）

- 路由一致性：一致/部分一致/不一致
  - 证据：...
  - 影响：...
  - 建议：...

- 安全头一致性：一致/部分一致/不一致
  - 证据：...
  - 风险：...
  - 建议：...

- 安全报告时效性：一致/部分一致/不一致
  - 证据：...
  - 风险：...
  - 建议：...
```

## E. 优先级映射（用于 Backlog）

- P0：出现“不一致”且涉及越权、密钥、敏感数据暴露、生产防护失效
- P1：为“部分一致”，会导致误导性文档或中等安全/稳定性风险
- P2：文档可读性、结构性改进、非关键一致性优化
