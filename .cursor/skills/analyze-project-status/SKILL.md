# 分析项目现状

## 目标

在**不凭空猜测**的前提下，快速建立对项目“现在是什么样”的共同认知，并输出两类产物：

- **现状报告（Markdown）**：摘要、现状概览、关键风险/问题、机会点、推荐下一步
- **改进 Backlog（可执行）**：按优先级拆成任务，写清验收标准与影响范围

## 适用场景（触发词）

当用户提到以下任一诉求时启用本技能：

- “分析项目现状 / 现状盘点 / 代码体检 / 健康检查”
- “架构梳理 / 模块划分 / 依赖关系”
- “安全审计 / 风险点 / 安全加固建议”
- “质量提升 / 测试覆盖 / CI / lint / 类型检查”
- “技术债 / 重构路线图 / 优先级计划”

## 工作方式（强约束）

- **优先引用证据**：每个结论尽量对应“文件/配置/命令输出”的证据来源。
- **先广后深**：先快速定位“项目类型 + 入口 + 依赖 + 运行方式”，再深入风险域（安全/质量/运维）。
- **区分事实与推断**：事实直接写；推断必须标注“推断”并给出依据。
- **尽量可复用**：输出中包含“如何复核”的最小命令/步骤。

## 输入（从用户/仓库获得）

若用户没有额外提供信息，默认通过仓库自动发现：

- 项目结构（关键目录、入口文件）
- 依赖与版本（Python/Node/Java 等按实际情况）
- 运行与部署方式（docker-compose、Makefile、脚本、CI）
- 安全与配置管理（密钥、环境变量、headers、鉴权）
- 测试与质量门禁（测试框架、覆盖率、lint、类型）
- 文档现状（README、架构文档、安全报告/路线图）

## 分析清单（按模块）

详细检查点见同目录的 [checklist.md](checklist.md)。
若仓库是当前 CAutoD FastAPI 项目，必须同时使用 [fastapi-cautod-profile.md](fastapi-cautod-profile.md) 的专用检查。

最低要求覆盖：

- **项目画像**：语言/框架、模块边界、入口、数据流、外部依赖（DB/缓存/消息/第三方）
- **可运行性**：本地启动方式、环境变量、迁移/初始化、seed、常见失败点
- **安全基线**：鉴权授权、密钥管理、CORS/CSRF、security headers、依赖风险、审计报告一致性
- **质量基线**：测试存在性、lint/format、类型检查、错误处理与日志、异常与监控
- **运维基线**：容器化/部署脚本、环境隔离、配置分层、备份恢复（如涉及数据）

## 输出模板（必须遵守）

按以下结构输出（不要额外发散章节名）：

```markdown
# 项目现状分析：<项目名或目录名>

## 执行摘要
- **结论**：<一句话总结当前健康度>
- **最优先的 3 件事**：
  1. <行动项 1>
  2. <行动项 2>
  3. <行动项 3>

## 项目画像
- **技术栈**：<语言/框架/关键库>
- **入口与运行**：<入口文件/启动命令/环境变量来源>
- **模块与边界**：<关键模块、责任、依赖方向>
- **外部系统**：<DB/Redis/消息队列/第三方 API>

## 现状发现（带证据）
### 做得好的
- <要点>（证据：`path/to/file` 或命令输出摘要）

### 风险与问题（按严重度）
- 🔴 **高**：<问题>（影响：…｜证据：…｜建议：…）
- 🟠 **中**：...
- 🟡 **低**：...

## 改进 Backlog（可执行）
| P | 任务 | 影响范围 | 验收标准 | 预估工作量 | 依赖/阻塞 |
|---|------|----------|----------|------------|-----------|
| P0 | ... | ... | ... | ... | ... |

## 复核与下一步
- **建议的验证方式**：<最小复核命令/步骤>
- **若要继续**：<你下一轮可以做的 2-3 个深入方向>
```

## 常用信号与默认判断（用于优先级）

- P0：会导致数据泄露/越权/密钥泄露/无法部署/频繁宕机/无法定位问题
- P1：明显的可靠性与质量隐患（无测试、无 lint、错误处理薄弱、日志缺失）
- P2：工程体验与长期维护成本（结构混乱、重复代码、文档缺失）

## 附：当仓库是 FastAPI（常见项目）时的特定检查

- 路由聚合方式（`apps/routes`、`APIRouter`）、依赖注入、安全依赖
- 配置来源（`.env`、环境变量、`pydantic settings`）
- 中间件：CORS、安全响应头、限流、请求 ID、日志
- OpenAPI/Docs 暴露策略（生产环境是否关闭或鉴权）

## CAutoD FastAPI 专用模式（强制）

当仓库根目录为 `cautod_fastapi` 或检测到以下文件时，进入专用模式：

- `apps/routes/`
- `core/security_headers.py`
- `SECURITY_REPORT.md`

专用模式要求：

1. **固定一致性检查**（必须执行并给出结论）
   - 路由实现 vs 文档描述（重点检查 `apps/routes`）
   - 安全响应头实现 vs 安全报告（重点检查 `core/security_headers.py` 与 `SECURITY_REPORT.md`）
   - 安全报告中的“已实现/待改进”是否仍与代码一致
2. **结论表达规则**
   - 每条一致性结论使用：`一致 / 部分一致 / 不一致`
   - 对“部分一致/不一致”必须给出证据路径和修复建议
3. **输出补充章节**
   - 在“现状发现（带证据）”后增加：
     - `## 专项一致性核对（CAutoD FastAPI）`
     - 至少包含 3 条：路由一致性、安全头一致性、安全报告时效性

具体检查步骤与模板见 [fastapi-cautod-profile.md](fastapi-cautod-profile.md)。
